## Spacing Scale

Declared values (must be multiples of 4). All values derived from observed Tailwind utility usage in `app/setup/components/`.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gap between status dot and label text (`gap-3` observed = 12px for larger targets; 4px for inline tight pairs) |
| sm | 8px | Inline padding within badges (`px-2.5 py-0.5` = 10px/2px; tight elements) |
| md | 16px | Default element padding — `px-5` (20px) / `py-4` (16px) in check rows |
| lg | 24px | Section-level padding — `p-6` in `TopSummary` |
| xl | 32px | Not currently used; available for future layout gaps |
| 2xl | 48px | Not currently used; available for major section breaks |
| 3xl | 64px | Not currently used; available for page-level spacing |

Exceptions:
- Touch target minimum: 44px tall — all interactive `<details>` summaries use `py-4` (16px) on `text-sm`, achieving ~44px min-height
- New deploy section check rows follow `px-5 py-4` to match existing `CheckRow` pattern exactly

## Typography

All sizes observed directly from `app/setup/components/` — no changes permitted. New health check copy must use the same sizes.

| Role | Size | Weight | Line Height | Tailwind Class | Usage |
|------|------|--------|-------------|----------------|-------|
| Body / check label | 14px (text-sm) | 400 (normal) | 1.5 | `text-sm text-zinc-200` | Check labels, section descriptions, detail lines |
| Label / caption | 12px (text-xs) | 400 (normal) | 1.5 | `text-xs text-zinc-400` | Check detail, sub-detail, evidence, next action |
| Section heading | 14px (text-sm) | 600 (semibold) | 1.5 | `text-sm font-semibold` | Section titles in `VerificationSection`, status labels |
| Page heading | 24px (text-2xl) | 600 (semibold) | 1.2 | `text-2xl font-semibold text-white` | `TopSummary` primary summary text |

Weights in use: **400** (regular) and **600** (semibold). No other weights permitted in this phase.

Mono stack (`ui-monospace, SFMono-Regular, Menlo, Monaco, Consolas, monospace`) is reserved for `<CodeBlock>` inline copy (env var names, commands, URLs). Applied at 12px / weight 400.

## Copywriting Contract

This phase produces copy in three surfaces: the README markdown deploy section, the new Deploy Readiness `VerificationSection`, and updated `/setup` check rows.

### Primary CTA

| Element | Copy | Surface |
|---------|------|---------|
| Deploy button badge | `Deploy with Vercel` | README badge alt text (Vercel provides visual) |
| Primary action (post-deploy) | `Verify at /setup` | README step 3 text |
| ActionLink in TopSummary | `Reload checks` | `/setup` — already exists, no change |

### Readiness Check Copy

New check rows added to the **Deploy Readiness** section in `/setup`. Follow the `CheckRow` shape: `label` (primary), `detail` (context), `nextAction` (imperative, one sentence).

| Check | Status | label | detail | nextAction |
|-------|--------|-------|--------|------------|
| NEXTAUTH_URL match | pass | `NEXTAUTH_URL matches deployment host` | `Configured host matches current request.` | — |
| NEXTAUTH_URL mismatch | warn | `NEXTAUTH_URL does not match deployment host` | `Configured: {configuredHost} — current: {currentHost}` | `In Vercel, set NEXTAUTH_URL to https://{currentHost} and redeploy.` |
| NEXTAUTH_URL missing | fail | `NEXTAUTH_URL is not configured` | `Auth redirects will fail until this is set.` | `In Vercel → Settings → Environment Variables, set NEXTAUTH_URL to your deployment URL, then redeploy.` |
| Redis present on Vercel | pass | `Realtime backend: Redis` | `Mission Control live stream is active.` | — |
| Redis absent on Vercel | warn | `Live stream requires Redis on serverless` | `Running in-memory mode. Each serverless invocation has a fresh event bus — Mission Control will not show live decisions.` | `Create a free Upstash Redis instance at upstash.com and add UPSTASH_REDIS_REST_URL and UPSTASH_REDIS_REST_TOKEN to Vercel environment variables.` |
| Redis absent (local) | info | `Realtime backend: in-memory` | `Acceptable for local development.` | — |
| CRON_SECRET present | pass | `CRON_SECRET is configured` | `Cron routes are protected.` | — |
| CRON_SECRET absent | warn | `CRON_SECRET is not set` | `Cron routes (/api/cron/*) are unprotected and signal processing may not run.` | `Generate with: openssl rand -hex 32 — then add to Vercel → Settings → Environment Variables.` |

### Empty States

Phase 1 does not introduce any data-bearing empty states. The `/setup` page always renders check results (never empty). Not applicable.

### Error States

| Scenario | User-visible copy | Surface |
|----------|-------------------|---------|
| Schema tables missing (existing check, no change) | `label: "Core tables not found"` / `nextAction: "Run npm run db:push against your database."` | `/setup` VerificationSection (existing — do not change copy) |
| NEXTAUTH_URL missing (new) | See check table above | `/setup` Deploy Readiness section |
| All deploy checks blocked | `TopSummary` `blocked` state — `summary` field from `getReadinessReport()`: `"Deploy configuration needs attention."` | `/setup` TopSummary |

### Destructive Actions

Phase 1 introduces no destructive actions. No confirmation dialogs, destructive CTAs, or delete flows. Not applicable.

## Interaction Contract

| Interaction | Behavior | Pattern |
|-------------|----------|---------|
| New Deploy Readiness section — collapsed state | Collapsed when all checks pass; expanded when any check is warn/fail | Existing `<details open={!allPass}>` logic in `VerificationSection` — automatic |
| Warn check row — next action visibility | `nextAction` text is always visible inline (no expand/collapse within a row) | Existing `CheckRow` renders `check.nextAction` as `text-xs text-zinc-400` — automatic |
| README deploy button click | Opens `https://vercel.com/new/clone?...` in new tab (standard link behavior) | Markdown badge link — no JS |
| `/setup` reload | Full server-side navigation to `/setup` — no client state | Existing `ActionLink href="/setup"` in TopSummary |
