**Fix 3 — Array item validation (SEC-03, per D-04):**
In `app/lib/validate.js` function `validateField()`, in the `case 'array':` block (around line 106), after the `maxItems` check, add per-item string type and length validation:
```javascript
case 'array':
  if (!Array.isArray(value)) return `${key} must be an array`;
  if (rule.maxItems && value.length > rule.maxItems) return `${key} exceeds max items of ${rule.maxItems}`;
  // SECURITY: Validate individual array items are strings with bounded length
  for (let i = 0; i < value.length; i++) {
    if (typeof value[i] !== 'string') return `${key}[${i}] must be a string`;
    if (value[i].length > 500) return `${key}[${i}] exceeds max length of 500`;
  }
  break;
```
The 500-character limit is generous for system names, side effects, and artifact paths while preventing abuse.

**Fix 9 — Remove dead PUBLIC_ROUTES entry for /api/actions (SEC-04, per D-01):**
In `middleware.js`, the PUBLIC_ROUTES array on line 37 contains:
```javascript
'/api/actions/[^/]+', // Allow public decision data for replay
```
The matching logic on line 1051 uses `pathname.startsWith(route)` — since `startsWith` is not regex-aware, this entry never matches any real pathname. It is dead code that appears to make `/api/actions/:id` public but does not.

**Decision:** Remove this dead entry entirely. The comment says it enables replay data, but `/replay` is already in PUBLIC_ROUTES and replay pages should fetch data through their own server-side data fetching, not through a public API route. If replay genuinely needs public action access, that should be implemented as a dedicated read-only replay endpoint (out of scope for this phase), not a regex in a startsWith list.

Remove the line:
```javascript
'/api/actions/[^/]+', // Allow public decision data for replay
```
from the PUBLIC_ROUTES array. This eliminates a confusing auth bypass vector that would become a real vulnerability if the matching logic were ever changed to use regex.
