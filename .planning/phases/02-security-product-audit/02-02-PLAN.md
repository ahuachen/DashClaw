**Governance Loop Verification (PROD-01, per D-09):**
Trace the complete governance loop through source code, verifying each step:

1. **Guard step**: Read `POST /api/guard` → `validateGuardInput()` → `evaluateGuard()`. Verify: input is validated, risk score is computed server-side, policies are fetched and filtered by org_id, decision is saved to guard_decisions table, response includes decision + risk_score + matched_policies.

2. **Create Action step**: Read `POST /api/actions` → `validateActionRecord()` → `scanSensitiveData()` → `createActionRecord()`. Verify: sensitive data is redacted before storage, action is scoped to org_id, event is published for realtime.

3. **Update Outcome step**: Read `PATCH /api/actions/:id` → `validateActionOutcome()` → update action_records. Verify: status transitions are validated (only running/pending states can be updated), org_id scoping is enforced on update.

4. **Signals step**: Read `GET /api/cron/signals` → `computeSignals()`. Verify: scans recent actions, computes 7 signal types, publishes events, fires notifications.

5. **Human Approval sub-path**: Read `POST /api/approvals/[actionId]`. Verify: admin role required, action must be in pending_approval state, approval is recorded.

For each step, note: auth mechanism used, input validation present, org scoping correct, error handling adequate.

**Persona 2: Startup CTO (3-5 agents)**
